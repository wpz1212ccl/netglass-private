## 0. 约束与目标

- **视觉语言不变**：弹簧几何、先慢后快、过冲回稳、错峰交叉淡入、35px squircle、纯 CSS 玻璃渐变、呼吸灯三态色（绿/橙黄/红）。任何视觉取舍进 §5 决策点。
- **行为默认不变**：本地状态 ≤2-3s 反映（19:44 已确认）、隐藏时采样连续（spec.md:153）、260ms 前台轮询（14:50 决策保留）、不切 native（14:40 决策）。
- **目标**：电池供电常驻无感。稳态单核 CPU：隐藏 <0.3%、岛 <5%（stretch ≤2%）、展开 <8%；岛×DC 边际功耗 <0.5W（放电实测）；私用内存能降尽降（WebView2 架构地板见 D5）。
- **功耗视角**（全树路估算，量级待放电校准）：隐藏 0.1–0.3W 可忽略；岛可见净增 0.5–2W（8h≈7–27% 电池）= 真正缺口。电池敌人是唤醒频率+持续出帧，不只是 CPU%。

## 3. 优化项（实施级）

### P0-1a 展开态暂停呼吸灯（零视觉变化，无决策）
- 现状：`src/index.html:145` `.mini` 用 `visibility:hidden`（不取消动画），展开态看不到呼吸灯却照付 120Hz 合成成本（MDN visibility 定义核验）。
- 改法：`.card:not(.collapsed) .mdot{animation-play-state:paused}`。胶囊态呼吸完全保留。
- 预期：展开态 GPU+renderer 合成基线大降（叠加后展开 <8%，stretch ≤4%）。

### P0-1b `.mdot` 独立合成层（零视觉变化，无决策）
- 现状：呼吸灯带 box-shadow，opacity/scale 未完全合成化，renderer 每帧样式/重光栅（实测 8–9.8% 单核）。
- 改法：`.mdot` 加 `will-change:transform,opacity`，阴影一次光栅、动画纯合成。
- 预期：renderer 份额大降；GPU 仍按刷新率出帧 → 与 P0-1c 叠加。

### P0-1c 胶囊态呼吸灯降频 / DC 暂停【决策 D1】
- 现状：`src/index.html:183-192` `.mdot` `animation:mdot-breathe 2s … infinite`（opacity+transform），120Hz 合成；岛稳态 GPU 10.5–13.5% + renderer 8–9.8% 单核（两路独立实测）。
- 改法：删 infinite CSS 动画，改 JS 驱动 ≤15fps：`setInterval(66ms)` 按正弦表写 `style.opacity/transform`（2s 周期 30 帧，6px 圆点慢动作视觉连续）；颜色仍走现有 `transition:background-color .4s`；`net-leave`/隐藏时 `clearInterval`，`net-mode` 恢复。**DC 档**：电池下静态点（保留绿/橙/红三态色），插电恢复呼吸——与已落地「DC 停外网探针」同一语言。保留 `.acc/.cat` 换色逻辑不动。
- 预期：岛稳态总 ≤2% 单核；岛×DC 边际 <0.5W。
- 视觉影响：呼吸由 120fps 变 15fps 步进；需目视/截图验收（D1）。诚实边界：保留平滑呼吸=保留持续产帧，15fps 是观感与功耗的折中。
- 验收：岛稳态 60s×3 ≤2%；呼吸观感 rubric ≥8/10；三态色闭环回归。

### P0-2a 隐藏时同步 WebView2 IsVisible=false（零视觉变化，无决策）
- 现状：`win.hide()`（main.rs:443）只走 tao `SW_HIDE`；wry `ICoreWebView2Controller::IsVisible` 恒 TRUE（tauri-runtime-wry 2.12.3 lib.rs:3381、tao 0.37.2 window_state.rs:408、wry 0.57.2 webview2/mod.rs:620/1664 源码核验）。现隐藏 0.78% 靠 Chromium 遮挡检测兜底。
- 改法：隐藏路径经 `with_webview` 调 `controller.put_IsVisible(false)`，显示路径 `put_IsVisible(true)`（MS 官方对 minimize/hide 的明确建议）。
- 预期：隐藏态渲染管线真正停摆，与 P0-2b 叠加 → ≤0.3%。

### P0-2b 隐藏时 TrySuspend【决策 D2】
- 接口定稿（前端路一手来源 + 本地绑定核验）：`ICoreWebView2_3::TrySuspend/Resume/IsSuspended`（SDK ≥1.0.774.44；本机 Runtime 157 远超）；webview2-com-sys 0.39.1 bindings.rs:43030/43042 可用。**调用前提 IsVisible=false**（P0-2a 先做），否则 ERROR_INVALID_STATE；best-effort；变可见自动 resume；恢复路径先查 IsSuspended 再 Resume。
- 改法：隐藏路径 put_IsVisible(false) → TrySuspend；显示路径 Resume → put_IsVisible(true) → show。与现有「隐藏停 emit/探针」叠加。
- 预期：隐藏 CPU ≤0.3%（配套 flag 后 0.02–0.1% 估算）；**working set 显著下降**；私用 150–200MB 估算（宽区间、低置信，仅 renderer 可回收，browser/GPU/utility 固定开销仍在）。验收 WS 与私用双口径（§6）。
- 风险：恢复首帧延迟（实测验收）；恢复前 emit 会丢——已停发，无冲突。

### P0-3 内存旋钮定稿：MemoryUsageTargetLevel **不采用**；browser args 逐项 A/B
- `ICoreWebView2_19::MemoryUsageTargetLevel`（SDK ≥1.0.1823.32，bindings.rs:41265）官方原文：可能把内存换出到磁盘，脚本再跑即换回。本项目胶囊态脚本 1Hz 常驻 → 换出/换回 churn + 磁盘 I/O，**电池场景反向优化**，否决。
- 内存收益主来源 = P0-2b 挂起回收 + P0-4/P0-5 二进制瘦身 + P1-7 层清理。
- `additionalBrowserArgs`（`app.windows[].additionalBrowserArgs`，tauri-utils 2.10.2 config.rs:1951/2137，**创建期**）：
  - **替换陷阱**：wry 0.57.2 webview2/mod.rs:309 `unwrap_or_else`——一旦设置默认串整条丢失，**必须自带** `--disable-features=msWebOOUI,msPdfOOUI,msSmartScreenProtection`（wry :312 默认）。
  - 配套高价值：`--enable-features=msWebView2TreatAppSuspendAsDeviceSuspend`（TrySuspend 时连 browser 进程定时器一起停）；`--enable-features=msWebView2SimulateMemoryPressureWhenInactive`（促释放缓存，可能拖慢恢复首帧，A/B）；`--disable-features=SpareRendererForSitePerProcess`（**先用 Browser Task Manager 确认 7 进程里真有 spare renderer 才加**，否则零收益）；`--disable-features=msFloatyMode`（官方建议 WebView 关）。
  - 低价值不默认：`--edge-webview-is-background`（首帧时机须验）、`msWebView2CodeCache`（内联 script 收益极小）。
  - **禁止**：`--disable-gpu`/`--disable-gpu-compositing`（官方：GPU 对性能 critical，软栅化反压 CPU）；`--disable-background-timer-throttling`（方向反）；`--no-sandbox`（仅测试）；`--single-process`（不在官方支持表；沙箱边界消失、渲染崩溃=整应用崩溃；**无独立渲染进程可回收 → TrySuspend 收益被摧毁**，Chromium content_switches.cc 一手注释）。
  - 纪律：集中一处、可一键回退、逐项 A/B，不一次全开（微软明言生产慎用 flag，wry 默认串除外）。

### P1-1 加速器检测改廉价实现，**保持 2s 反映**（行为不变）

- 预期：0.7% → <0.1%；开/停加速仍 ≤2-3s 反映。
- 风险：归属分支变多 → 补单测（现有 22 个全绿为前提）。
- **验收回归记录**：首版把 accelerating 挂在 10s 进程缓存下，临时 core.exe 实测新启动加速器 ≤10s 才变红，违反 ≤2-3s 承诺；已修为 accelerating 直接由监听表+hosts 判定（2s），缓存仅供「在运行」展示并立即并入加速中标签。复测见 sessionlog。

## 4. 明确不动（核验属实 / 用户满意 / 建议被否决）

- **anim apply 与拖动线程不节流到 60Hz**：子代理建议被否决——屏幕 120Hz（Win32_VideoController 实测），现 8ms apply≈125Hz 正好匹配（anim.rs:217、main.rs:733）；形变/拖动是 bursts 非稳态，节流会牺牲手感。
- anim 空闲 `recv()` 零唤醒（anim.rs:210-215）；netmon 60s/5s 缓存与 GetIfEntry2 单读（netmon.rs:279-319）；隐藏采样连续；260ms 可见态轮询；不切 native；玻璃纯 CSS 无 backdrop-filter。
- 多显示器主屏口径（main.rs:248-260）为已知限制，本轮不扩 scope，仅记录。
- **呼吸周期 2s→4s 不省帧**（合成器仍按刷新率出帧），非性能手段，勿用。
- **animUntil 300ms 硬切**（index.html:427-433）属手感问题，性能轮不动（前端路 F6 同结论）。
- **固定大画布+CSS 画胶囊**否决：用常驻成本换瞬时成本，与不插电目标相反（前端路 F5 同结论）。

## 6. 验收协议（全树路定稿，主代理核验）

**口径**：单核% = Σ整树 CPU 秒增量÷采样秒×100；整机% = 单核%÷16，**两者必标禁混用**（旧文档 1.25% 误标即此坑）。整树按 ParentProcessId 递归；逐进程 `CommandLine --type=` 归因；报**中位+p90**，启动/退出尖峰不计。
**干净窗口规则**：采样前后比对 `%TEMP%\netglass-log.txt` 行数，出现 mode/anchor 增量即污染作废重测。

| 场景（60s×3 / 10s 间隔） | 进入方式 | 主指标 | 阈值（单核·整树） |
|---|---|---|---|
| 隐藏×AC/DC | 托盘单击 / 拔电 | CPU、私用MB、放电W | **<0.3%**（stretch <0.2%） |
| 岛×AC/DC | 应用前台 / 拔电+前台 | CPU、逐进程归因、DC 30min charge 斜率→W | **<5%**（stretch <2%）；DC 边际 **<0.5W** |
| 展开×AC/DC | 桌面前台 2s、无流量 | CPU | **<8%** |
