## 1. 产品定义

NetGlass（网镜）是一个常驻 Windows 桌面的浅色玻璃小卡片。它在 1 秒的节奏里回答三个问题：

1. 我这个出口现在跑多快？（一个大数字）
2. 这个速度是哪条连接在跑？（宽带拨号 / Wi-Fi）
3. 我开着的加速器现在通不通？（一行状态灯）

它不加速、不限速、不改网络配置，只做"看见"。

### 1.1 典型场景

- **场景 A**：下载游戏时瞄一眼，确认是不是真的跑满了 100 Mbps 的拨号线。
- **场景 B**：GitHub 拉代码很慢，切到卡片上看到 Watt Toolkit 那行是"未启用"，于是知道该去开加速。
- **场景 C**：合上笔记本再打开，发现卡片上 Wi-Fi 那一行是"已关闭"而不是"0 KB/s"，立刻知道是无线被关了，而不是网断了。

### 1.2 成功标准

- 下载一个文件时，卡片读数和实际下载速度的偏差不超过 5%。
- 网络状态变化（关闭 Wi-Fi、断开拨号、关掉加速器）在 5 秒内反映到界面上。
- 连续运行 24 小时不崩、不明显吃电、位置和锁定状态都记得住。
- 一眼看上去是一个"桌面上的小组件"，不是一块监控面板。

## 4. 界面规格

### 4.1 画布

| 项 | 规格 |
|---|---|
| 逻辑尺寸 | 320 × 200（固定，不可缩放） |
| 圆角 | 22 |
| 内边距 | 上 16 / 左右 18 / 下 0 |
| 窗口实际尺寸 | 320 × 200，不预留展开区 |
| 任务栏 | 不出现 |
| Alt+Tab | 不出现 |
| 缩放 | 跟随系统 DPI，坐标一律按逻辑像素记录 |

**关于"展开"的规格变更（重要）**：视觉原型里卡片 hover 时从 200 长到 268。真实窗口中**不采用这个做法**，理由有两条：

1. 若把窗口做成固定的 268 高、未展开时底部 68 像素透明，这块透明区仍然是窗口矩形的一部分，会吞掉鼠标点击（点不到桌面图标），违背产品初衷。
2. 若在 hover 时实时改变窗口高度，DWM 的玻璃背景需要重绘，正是官方库文档里点名的掉帧场景，会毁掉"丝滑"。

因此 v1 的展开改为**同尺寸内容切换**：卡片不长大，而是轻微上浮、详情层淡入并替换曲线区域。动效观感见 4.7。若将来一定要窗口生长，需要单独的窗口尺寸动画方案，不在 v1。

### 4.2 布局

从上到下四段，纵向坐标以卡片顶边为 0：

| 区域 | 范围（y） | 内容 |
|---|---|---|
| 状态行 | 16 – 32 | 线性符号 13×13、连接名 13px、右侧状态文字 11px |
| 主数字区 | 47 – 93 | 大号下行数字 46px + 单位；右侧上行数字 + 单位 |
| 底栏 | 108 – 122 | 两个「符号 + 文字」项：Wi-Fi、代理。无底色、无边框 |
| 曲线区 | 134 – 200 | 60 点面积曲线，左右出血到卡片边缘 |

详情层（hover 时）占据 98 – 182，2 列 × 3 行：延迟 / 丢包、峰值 / 链路、代理 / 出口。

卡片上**没有任何按钮、角标或图标底色**：苹果的小组件没有 chrome。锁定只通过全局快捷键与托盘菜单触发。

### 4.3 排版

| 元素 | 字号 | 字重 | 字距 | 其他 |
|---|---|---|---|---|
| 连接名 | 13 | 600 | -0.012em | 主文字 |
| 状态文字 | 11 | 450 | 0 | 46% 黑 |
| 大数字 | 46 | 600 | -0.042em | 等宽数字 |
| 单位 | 13 | 500 | -0.005em | 三级色 |
| 上行数字 | 14 | 560 | 0 | 二级色，等宽数字 |
| 上行单位 | 11 | 500 | 0 | 三级色 |
| 底栏文字 | 11 | 500，数值 600 | 0.004em | — |
| 详情标签 / 数值 | 10.5 | 450 / 550 | -0.005em | 数值等宽 |

字体：**内置 Inter Variable**（OFL 许可，SF Pro 最接近的开源替代），回退顺序为 SF Pro Text → Segoe UI Variable → PingFang SC → 微软雅黑。所有数字必须启用等宽数字特性，否则数值跳动时整行会左右抖，这是"廉价感"的主要来源。

### 4.4 色彩（浅色玻璃）

| Token | 值 | 用途 |
|---|---|---|
| 玻璃底 | 白 74% → 白 58% 垂直渐变；真实窗口由 Mica 提供 | 卡片背景 |
| 内发丝边 | 白 96%，0.5px | 顶边厚度 |
| 外圈 | 白 72%，0.5px | 卡片轮廓 |
| 主文字 | #12151A | 大数字、连接名 |
| 二级文字 | 黑 56% | 上行、底栏、详情数值 |
| 三级文字 | 黑 40% | 单位、状态文字、详情标签 |
| 发丝分隔线 | 黑 8.5% | 详情格线 |
| 强调蓝 | #0A84FF | 曲线、锁定提示 |
| 系统绿 | #34C759 | 连接正常 |
| 系统橙 | #FF9F0A | 代理未启用 |
| 故障红 | #FF3B30 | 探测失败 |
| 外阴影 | #121C30 30% + 8% | 卡片投影（双层） |

**玻璃的边界**：模糊效果只能由系统窗口特效（浅色 Mica，失败时降级为带浅色着色的亚克力）提供。CSS 只能做高光、描边、阴影与渐变，不能承担模糊 —— 透明窗口背后是 DWM 合成的桌面，CSS 的模糊滤镜看不见桌面内容。

### 4.5 组件视觉

- **符号**：状态行 13×13，底栏 11×11；1.7–1.8px 描边、圆头圆角，风格对齐 SF Symbols。状态行用地球（表示出口），底栏 Wi-Fi 用带斜线的扇形，代理用闪电。
- **大数字**：与单位按基线对齐，单位距数字右侧 5。
- **上行**：位于主数字区右端，箭头 9×9，与数字基线对齐。
- **底栏**：无底色、无边框、无圆角，纯「符号 + 文字」，两项间距 14；数值使用 600 字重。
- **曲线**：底部出血，填充强调蓝 30% → 9% → 0，描边 1.5px；左端 35% 透明过渡到右端不透明，表示"越右越新"。路径使用中点二次贝塞尔并做三点平滑，禁止折线。
- **不使用任何胶囊、按钮、角标或图标底色**。

### 4.6 状态矩阵

| 卡片状态 | 触发条件 | 视觉 |
|---|---|---|
| 启动中 | 启动后第一拍数据到达前（≤1.5 秒） | 大数字显示"—"，状态行"正在读取"，曲线为一条平直虚线 |
| 活跃 | 出口速率 ≥ 1 KB/s | 正常显示，颜色齐全 |
| 空闲 | 出口速率 < 1 KB/s 持续 3 秒 | 大数字"0.0"，状态点去掉光晕，文字降为二级色 |
| 已断开 | 出口适配器不可用，但存在其他可用连接 | 状态行"已切换"，大数字显示新的出口速率 |
| 全部关闭 | 所有候选适配器均不可用 | 大数字"—"，状态行"无网络"，曲线隐藏，卡片整体降到 70% 不透明度 |
| 代理未启用 | 系统代理关闭且加速器进程未运行 | 底栏代理项为橙色"未启用" |
| 探测失败 | 连续 3 次探测失败 | 底栏代理项为红色"不通"，保留最后一次成功时延 |
| 已锁定 | 用户按下锁定快捷键 | 整窗点击穿透；状态文字短暂显示"已锁定"2 秒后恢复 |
| 已隐藏（全屏） | 检测到全屏应用 | 窗口隐藏，采样继续，状态不变 |

### 4.7 动效

| 场景 | 规格 |
|---|---|
| 数字变化 | 弹簧过渡，刚度 175、阻尼 21；每次数据到达时启动 |
| 卡片 hover | 上浮 1px、缩放 1.004，300ms，`cubic-bezier(0.16, 1.02, 0.32, 1)` |
| 详情层 | 淡入 + 上移 4px，240ms，延迟 40ms；曲线完全淡出（不叠字） |
| 离开 hover | 反向，160ms |
| 状态切换 | 交叉淡入 200ms，不做位移动画 |
| 曲线推进 | 每秒整段左移一格，路径在 300ms 内线性过渡 |
| 锁定反馈 | 状态文字短暂显示"已锁定"，2 秒后回到"已连接" |
| 全屏进出 | 窗口直接隐藏/显示，不做淡入淡出（避免用户在游戏中看到残影） |

所有动效必须遵循系统"减少动画"设置：开启时数字改为直接跳变、hover 只改透明度。

### 4.8 深色壁纸

不提供深色主题。原因是玻璃的底色由系统的浅色 Mica / 亚克力提供，其着色不随壁纸明暗变化；卡片本身始终是"浅色玻璃 + 深色文字"。在深色壁纸上它会呈现为一层略亮的磨砂面板，仍可读。v1 不做自动反转。

| 编号 | 行为 |
|---|---|
| IX-1 | 鼠标进入卡片：120ms 后触发 hover 态；离开：200ms 后恢复 |

| IX-7 | 托盘左键单击：显示/隐藏窗口（不改变锁定与自启状态） |
| IX-8 | 托盘右键：展示菜单，含"显示卡片 / 锁定 / 开机自启（勾选）/ 退出" |

## 6. 数据采集规格

### 6.1 采样

| 项 | 规格 |
|---|---|
| 周期 | 1000 毫秒，允许 ±50ms 抖动 |
| 首次采样 | 启动后立即建立基线，不显示数值 |
| 第二拍 | 首次显示真实数值，最迟 1.5 秒 |
| 数据来源 | 系统接口计数，64 位，单调递增 |
| 时钟 | 使用单调时钟计算间隔，避免系统时间被校准导致速率跳变 |

### 6.2 差分与异常

- 本次计数小于上次：判定为计数器重置（重播、唤醒、驱动重载），本拍速率记 0，重建基线，并在 1 秒内不参与平滑。
- 接口从表中消失：对应行移除；若它是出口，立即重新选出口。
- 新增接口：出现在候选列表后，经过一拍基线再参与显示。
- 接口索引变化（重播典型表现）：按接口标识重新绑定，不沿用旧索引。
- 速率计算为字节/秒，显示层再做单位换算与平滑。

### 6.3 出口识别

- 出口 = 当前默认路由指向的接口。
- 每次采样都核对默认路由，而不是只在启动时判断。
- 出口变化时：大数字在 200ms 内交叉淡入为新出口的数值，状态行同步更新连接名。
- 同一时刻只显示一个出口的速度；其他连接只在胶囊行以状态与数值体现。

### 6.4 Wi-Fi

| 项 | 规格 |
|---|---|
| 连接状态 | 事件驱动，连接/断开立即更新 |
| 信号、频段、速率 | 连接时取一次，之后每 10 秒刷新 |
| 射频关闭 | 状态为"已关闭"，不显示速率 |
| 未连接 | 状态为"未连接"，不显示速率 |
| 连接但速率为 0 | 显示"空闲"，速率 0.0 |

### 6.5 链路上限

- 每条连接读取协商速率（拨号为底层适配器的 100 Mbps）。
- 速度条按"当前速率 ÷ 协商速率"的比例绘制，不按固定刻度。
- 协商速率不可得时，采用满刻度并标注"未知"。

## 7. 代理与加速器规格

### 7.1 状态来源

| 来源 | 用途 | 刷新 |
|---|---|---|
| 系统代理设置 | 是否启用、指向哪个本地端点 | 5 秒 |
| 加速器进程名 | 是否在运行（Watt、SakuraCat 内核、UU） | 5 秒 |
| 本地端口监听 | 代理端点是否可用 | 5 秒 |
| 虚拟网卡名 | 是否处于 TUN 模式 | 5 秒 |
| Clash 兼容接口 | 可选，探测到才启用 | 10 秒 |

### 7.2 探测

| 项 | 规格 |
|---|---|
| 周期 | 30 秒，前后各 5 秒随机抖动 |
| 超时 | 单次 5 秒 |
| 目标 | 可配置，默认 github.com:443 |
| 直连路径 | 建立 TCP → TLS → 发出 HTTP 请求，分别记录 TCP 时延、TLS 时延、首字节时延 |
| 代理路径 | 仅在本地代理端口监听时执行；经该端口建立到目标的隧道 |
| 失败判定 | 连续 3 次失败 → 状态"不通"；成功 1 次即恢复 |
| 流量成本 | 每次数 KB，每小时 120 次，合计不超过 1 MB |
| 吞吐测试 | 仅手动触发；拉取 256 KB 后计算，结果保留展示 10 秒 |

探测失败只影响代理胶囊，**绝不影响大数字**。探针是旁路。

### 7.3 胶囊文案

| 状态 | 文案 | 颜色 |
|---|---|---|
| 未启用 | 代理 · 未启用 | 黄 |
| 仅监听 | 代理 · 待测 | 黄 |
| 正常 | 代理 · 38 ms | 绿 |
| 失败 | 代理 · 不通 | 红 |
| 正在测吞吐 | 代理 · 测试中 | 蓝 |

加速器名优先显示：若只有一个加速器在运行，显示其名称（如"Watt"）而不是"代理"。

## 9. 显示规则

### 9.1 单位与格式

| 速率范围 | 显示 |
|---|---|
| ≥ 1 MB/s | 1 位小数，单位 MB/s（苹果式：不显示两位小数） |
| 0.001 – 1 MB/s | 整数，单位 KB/s |
| < 1 KB/s | 0.0，单位 MB/s，并进入空闲态 |
| 无数据 | 破折号"—"，不显示单位 |

进制按 1024 换算。单位文字随数值切换，切换时不做动画，避免"单位在跳舞"。

### 9.2 平滑

- 显示值 = 上一显示值 × 0.65 + 本次原始值 × 0.35。
- 峰值保持：出现新的 60 秒峰值时，在详情层保留 1.2 秒的高亮，然后回落。
- 平滑只作用于显示，不作用于曲线原始数据。

### 9.3 曲线

- 保留最近 60 个采样点（约 60 秒）。
- 纵轴取最近 60 点的最大值并上浮 15%，最小值固定为 0。
- 全为 0 时不画面积，只画一条水平基线。

## 13. 边界与异常

| 编号 | 情况 | 期望行为 |
|---|---|---|
| EC-1 | 拨号重播后接口索引变化 | 自动重新绑定，数字从 0 平滑恢复，不出现负值或长时间空档 |
| EC-2 | 睡眠 8 小时后唤醒 | 首拍丢弃并重建基线，不显示跨睡眠的平均值 |
| EC-3 | 拔掉网线 | 3 秒内切到可用出口；无可用出口则进入"全部关闭" |
| EC-4 | 关闭 Wi-Fi 射频 | Wi-Fi 行显示"已关闭"，不是 0 |
| EC-5 | 代理软件打开但未点连接 | 显示"待测"→"不通"，不显示 0 ms |
| EC-6 | 代理端口被其他程序占用 | 探测失败进入"不通"，不影响主数字 |
| EC-7 | 探测目标 DNS 解析失败 | 归入"不通"，记录原因，不重试到下一轮 |
| EC-8 | 系统时间被校准 | 速率不受影响（单调时钟） |
| EC-9 | 显示器热插拔 / 分辨率变化 | 位置夹取到最近工作区，不重建窗口 |
| EC-10 | 中途修改系统缩放 | 窗口按逻辑尺寸重新换算，不闪烁 |
| EC-11 | 资源管理器重启 | 托盘重建、置顶恢复 |
| EC-12 | 加速器以管理员身份运行 | 只读状态检测不受影响；不做任何注入 |
| EC-13 | 配置文件损坏或权限不足 | 默认值启动，损坏文件改名备份，不弹窗 |
| EC-14 | 同时存在多个加速器 | 胶囊显示"代理"而非某个具体名字；详情层列出全部 |
| EC-15 | 4K 屏 200% 缩放 | 卡片物理尺寸翻倍，排版比例不变 |
| EC-16 | 无显卡加速 / 远程桌面 | 玻璃降级为半透明纯色面板，仍可读 |

## 14. 验收清单

发布 MVP-1 前必须全部通过：

1. 启动后 1.5 秒内出现卡片，无白闪、无黑块。
2. 下载一个 1 GB 文件，卡片下行读数与资源监视器偏差 ≤ 5%。
3. 上行读数在传文件到手机时正确增长。
4. 单击"断开连接"断掉宽带，3 秒内大数字归零或切换出口。
5. 关闭 Wi-Fi 射频，Wi-Fi 胶囊变为"已关闭"而非 0。
6. 拖动卡片到屏幕边缘，12 像素内自动吸附。
7. 重启程序，位置与锁定状态完全恢复。
8. 按 Win+D，卡片仍然可见。
9. 打开全屏视频，卡片隐藏；退出全屏，卡片恢复。
10. 锁定后点击卡片区域，能选中其下方的桌面图标。
11. 关闭再打开 SakuraCat，代理胶囊在 5 秒内变化。
12. 断开网络 10 秒再恢复，数字平滑恢复，无负值、无报错弹窗。
13. 睡眠唤醒后首屏数值合理，不是 8 小时的平均值。
14. 在 150% 和 200% 缩放下排版不溢出、不清糊。
15. 连续运行 24 小时，内存无增长趋势，CPU 平均 < 0.3%。
